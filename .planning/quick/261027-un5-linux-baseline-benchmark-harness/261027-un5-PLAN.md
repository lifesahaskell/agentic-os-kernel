## Planner additions (discretion; list each in the SUMMARY so the user can drop it)

- **A1** Config C1c: the C1b filter plus one load of `args[0]` placed before the syscall-number load. Reason: since Linux 5.11 the seccomp action cache precomputes an allow bitmap for any filter whose verdict depends only on arch and syscall number, so C1a and C1b skip BPF execution for allowed calls. C1c defeats the cache and measures real filter execution. The report must explain this.
- **A2** Bench `getppid_x1000`: time 1000 consecutive `getppid` calls and divide. Reason: the planner probe saw a 10 ns timer quantum against a ~130 ns call, so per-call medians resolve only in ~8 percent steps.
- **A3** TCP client sockets set `SO_LINGER {1,0}` (close sends RST); the listener lives in the measuring process and is drained with non-blocking `accept4` outside the timed region. Reason: avoids TIME_WAIT port exhaustion over ~700k connects and SYN drops (1 s retransmit) from a full accept queue on one CPU.
- **A4** Self-checks prove each restriction is active before measuring (seccomp mode and filter count, negative tests that must be denied). Reason: a restriction that silently failed to apply would read as 0 percent overhead.
- **A5** `run.sh` runs suites separately (`--suites`) and supports round ranges (`--rounds 1-3`) into one run directory. Reason: the executor's foreground command limit is 10 minutes, and background shells are forbidden.
- **A6** The S6 leg also runs with `cgroup.kill` as the kill mechanism when a delegated cgroup exists (configs `cgkill_L0/L1/L4`), interleaved with the pidfd configs. Reason: S6 states "cgroup killed within 1 s", and scoping-linux.md section 2.1 names `cgroup.kill` as the enforcement. This is also L10's `cgroup.kill` latency.
- **A7** Probe only: register a PSI trigger on the delegated leaf's `memory.pressure` and record success or errno. Reason: it decides what S8 needs, so the NOT MEASURED statement is accurate. No S8 latency is measured.
- **A8** Record the active LSM list via the `lsm_list_modules` syscall (461). Reason: securityfs is not mounted, and this list is what makes the BPF-LSM NOT MEASURED reason VERIFIED rather than assumed.

## Host facts from the planner probe (2026-10-27; orientation only, never report data)

- gcc 13.3.0, glibc 2.39, Python 3.12.3, strace present; perf and bpftool absent. Kernel `6.18.33.2-microsoft-standard-WSL2`, Landlock ABI 7, `CONFIG_BPF_LSM=y`, but `CONFIG_LSM` lacks `bpf` and `/proc/cmdline` has no `lsm=`. `lsm_list_modules` returned ids 100 110 105 107 101 111 (capability, landlock, yama, safesetid, selinux, ima); 109 (bpf) is absent. `kernel.unprivileged_bpf_disabled=2`. `/proc/pressure/{cpu,io,memory}` exist. `/proc/config.gz` is readable.
- Installed uapi headers are linux-libc-dev **6.8**. They lack `LANDLOCK_ACCESS_FS_IOCTL_DEV`, the `scoped` member of `struct landlock_ruleset_attr`, `LANDLOCK_SCOPE_*`, `struct pidfd_info` and `PIDFD_GET_INFO`. They do have `SO_PEERPIDFD` (77), `SO_PASSPIDFD` (76), `LANDLOCK_RULE_NET_PORT`, `CLONE_INTO_CGROUP`, `struct clone_args`, and `linux/lsm.h` with `LSM_ID_*`.
- Values from upstream `include/uapi/linux/landlock.h` and `include/uapi/linux/pidfd.h` at tag v6.18, fetched by the planner, go into `uapi_compat.h` under `AOK_` names. Landlock: ruleset attr = three `__u64` fields `handled_access_fs`, `handled_access_net`, `scoped` (24 bytes). FS rights are bits 0..15, EXECUTE (0) through IOCTL_DEV (15), so the full set is `0xFFFF`. NET: BIND_TCP bit 0, CONNECT_TCP bit 1. SCOPE: ABSTRACT_UNIX_SOCKET bit 0, SIGNAL bit 1. pidfd: `PIDFS_IOCTL_MAGIC 0xFF`, `PIDFD_GET_INFO = _IOWR(0xFF, 11, struct pidfd_info)`. `struct pidfd_info` is 72 bytes: `__u64 mask, cgroupid; __u32 pid, tgid, ppid, ruid, rgid, euid, egid, suid, sgid, fsuid, fsgid; __s32 exit_code; __u32 coredump_mask, __spare1`. Mask bits: PID 1<<0, CREDS 1<<1, CGROUPID 1<<2, EXIT 1<<3. Runtime checks (below) must confirm these layouts.
- Clocksource `tsc` (vDSO path; `clock_gettime` makes no syscall). Back-to-back `CLOCK_MONOTONIC_RAW` deltas came in multiples of 10 ns.
- lscpu: AMD Ryzen 9 7900X3D, 12 CPUs = 6 cores x 2 threads, Hypervisor vendor Microsoft. CPUs 2 and 3 share core 1. `/dev/kvm` is absent. `systemd-detect-virt` prints `wsl`.
- `/dev/shm` and `/run/user/1000` are tmpfs; `/` is ext4 on `/dev/sdd`, and the checkout lives on it. `/bin/true` is a dynamically linked PIE (merged /usr: `/bin` -> `/usr/bin`). `tcp_tw_reuse=2`, port range 32768-60999, somaxconn 4096.
- cgroup: the shell's own cgroup is `/init.scope` (root-owned). `/sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service` is owned by uid 1000, with `subtree_control` = `cpu memory pids`. Writing into it from `/init.scope` fails the cgroup v2 common-ancestor rule. These both succeeded: `systemd-run --user --wait --pipe --collect --quiet -p Delegate=yes -- ...`, which lands in `.../app.slice/run-uN.service`, owned by uid 1000, controllers `cpu memory pids`; and `systemd-run --user --scope -p Delegate=yes -- ...`. systemd 255.
- Commit signing: `commit.gpgsign=true`, `gpg.format=ssh`. If a commit fails with `ssh_askpass`, run `ssh-agent-init`, then `source ~/.ssh/agent.env`, and retry the same commit. If a passphrase is requested, stop and report. Never disable signing.

## Names and formats (shared by all tasks; use them exactly)

**Run directory.** `tools/linux-baseline/results/<RUN_ID>/`. A measured run uses `RUN_ID=$(date -u +%Y%m%dT%H%M%SZ)` chosen once and passed to every suite. Smoke runs use `RUN_ID=smoke-*`; `run.sh` recreates a smoke directory from scratch, and these directories are gitignored. For any other id, `run.sh` appends, and refuses with exit 3 if the requested (suite, round, config) already has rows. Files: `env.txt`, `run.log`, `micro.csv`, `broker.csv`, `deadline.csv`, `cgroup.csv`, `selfcheck.txt`, `cgroup-probe.txt`, `cgroup-behaviour.txt`, `summary.md`, `summary.csv`.

**CSV schema (every suite).** Header `suite,round,config,bench,n,warmup,min_ns,p50_ns,p90_ns,p99_ns,p999_ns,max_ns,mean_ns,errors`. One row per (process, bench). ns values are printed `%.3f`. Quantiles are nearest-rank over the round's samples sorted ascending: q-quantile = x[ceil(q*n)-1] for q in 0.5, 0.9, 0.99, 0.999; min = x[0], max = x[n-1]. `errors` counts calls that returned an unexpected result. Any errors > 0 makes the process exit 2 after writing its rows and its selfcheck line.

**Suites, configs, benches.**
- micro (fresh process per round x config; order C0 C1a C1b C1c C2a C2b C3 in every round). Benches run in this order in each process, each preceded by its warm-up:
  - `timer_pair`: N 1,000,000, warm-up 100,000.
  - `getppid`: N 1,000,000, warm-up 100,000.
  - `getppid_x1000`: N 2,000 batches, warm-up 200; the value is batch_ns/1000.
  - `openat_tmpfs`: N 200,000, warm-up 20,000.
  - `openat_rootfs`: N 200,000, warm-up 20,000.
  - `unix_connect`: N 50,000, warm-up 5,000.
  - `tcp_connect`: N 20,000, warm-up 2,000.
  - `fork_exec_wait`: N 1,000, warm-up 100.
  - `posix_spawn`: N 1,000, warm-up 100.
  - `unix_dgram_pingpong`: N 200,000, warm-up 20,000.
- broker (fresh process per round x variant; order `direct broker_noid broker_id egress_direct egress_broker`; bench `roundtrip`). N is 200,000 for direct, 100,000 for each broker variant, 20,000 for each egress variant; warm-up 10 percent.
- deadline: configs `pidfd_L0 pidfd_L1 pidfd_L4`, plus `cgkill_L0 cgkill_L1 cgkill_L4` when delegation=yes, interleaved in that order per round; 200 trials per config per round, 10 warm-up trials, deadline 10 ms after spawn. Benches: `deadline_to_wakeup`, `wakeup_to_reaped`, `deadline_to_reaped`, plus `deadline_to_empty` for cgkill. Clock: `CLOCK_MONOTONIC` for this suite only, because `timerfd` cannot use the raw clock. Record that in the report.
- cgroup (delegation=yes only): configs `spawn_fork spawn_clone3_into spawn_fork_move`, interleaved per round, bench `spawn_exec_wait`, N 1,000, warm-up 100. The behaviour legs (OOM, pids.max, clone3 functional check, PSI registration) run once, in round 1, and write `cgroup-behaviour.txt`.
- Smoke (`--smoke`): every N and warm-up divided by 50 and rounded up (minimum 20 samples, minimum 5 warm-up), deadline 10 trials, rounds 1-2, one OOM trial and one pids trial.
- Full run: rounds 1-5 (`--rounds` default `1-5`).

**selfcheck.txt.** One line per process, written at process end: the config or variant name, then space-separated `key=value` tokens with no spaces inside values.
- micro: `round= pid= Seccomp= Seccomp_filters= base_filters= NoNewPrivs= landlock=<none|fs|net_scope|fs_net_scope> neg_seccomp= neg_fs= neg_net= neg_scope_unix= neg_scope_signal= filter_insns= errors= result=`. Each neg_ value is `pass`, `fail` or `na`.
- broker_id: `round= so_peercred=ok so_peerpidfd=<ok|unsupported:ERRNO> pidfd_get_info=<ok|unsupported:ERRNO> pid_match=<yes|no> cgroupid_match=<yes|no> errors= result=`.
- Every other broker, deadline and cgroup process: `round= errors= result=`.
- `result=ok` only when every applicable check passed and errors=0, otherwise `result=FAIL`.

**env.txt keys.** `date_utc harness_rev harness_dirty uname_r uname_a cpu_model nproc cpu_pinned cpu_pinned_core_siblings wsl2 hyperv virt_systemd_detect kvm_dev clocksource cmdline config_lsm config_bpf_lsm active_lsms landlock_abi so_peerpidfd pidfd_get_info timer_res_ns timer_quantum_ns unprivileged_bpf_disabled psi gcc glibc shell_seccomp shell_nonewprivs top_cpu_before`, plus per suite invocation `loadavg_before_<suite>_<rounds>`, `procs_running_before_<suite>_<rounds>`, `loadavg_after_<suite>_<rounds>`, `elapsed_s_<suite>_<rounds>`, and `requested_<suite>_configs`, `requested_<suite>_rounds`. The format is one `key=value` per line.

**Summary definitions (summarize.py).** Per (suite, config, bench) over rounds:
- `med_p50` is the median of round p50s (likewise `med_p90`, `med_p99`, `med_p999`). `spread_p50_pct` = 100 x (max round p50 - min round p50) / med_p50 (likewise p99). `n_total` is the sum of n. Min and max are taken over rounds.
- Added overhead against the baseline: `added_p50_pct`, `added_p99_pct`, `added_p50_ns`, `added_p99_ns`. `within_noise=yes` when the [min, max] ranges of round p50 for config and baseline overlap.
- `stability`: `stable` below 10, `unstable` 10-25, `noise-dominated` above 25, on spread_p50_pct.
- Baselines: every micro config against C0. Broker: broker_noid and broker_id against direct, egress_broker against egress_direct, plus a derived row `broker_id_vs_noid`. cgroup: spawn_clone3_into and spawn_fork_move against spawn_fork. Deadline rows are absolute, with no baseline.
- summary.md opens with a verdict block: C0 micro stability counts, with unstable and noise-dominated bench names; the plausibility result for the two ASSUMED windows; NOT MEASURED legs copied from cgroup-probe.txt.
