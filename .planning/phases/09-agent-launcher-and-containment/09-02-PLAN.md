**User story (MVP):** **As** the researcher, **I want to** spawn each agent into its own cgroup with a pidfd-resolvable identity, narrowed Landlock and seccomp layers, and subtree freeze and kill, **so that** every later component has an unprivileged principal to key on.

<objective>
Bind each agent's identity record (`agent_id`, `on_behalf_of`, parent) to its cgroup id and make a peer resolve it from a pidfd (LNCH-02). Fill `src/identity.rs` (the stub 09-01 declared): the pidfd → `PIDFD_GET_INFO` → cgroup id → `/proc/PID/cgroup` path → drop `main` → nearest registered root resolution chain (D-09), the launcher-written registry keyed by `(boot_id, cgroup_id)` (D-06, D-08), the `SO_PEERCRED` fallback that reports its pid-reuse race, and the `aok-launch whois` subcommand. Re-create the xattr-forgery probe as a repo negative-control test (D-10).

Purpose: the registry and the `agent_id` path are what the Phase 10 broker reads through a pidfd and what the Phase 11 BPF-LSM policy keys on. Getting the resolution chain and its one-key invariant right now is what lets every later component trust a kernel-stamped principal.

Output: a complete `src/identity.rs`, `tests/identity.rs` proving a peer resolves the same `agent_id` from any task in the subtree and that the pidfd path and the fallback path agree, and `tests/xattr_forgery.rs` proving a `user.*` xattr is not a tamper-resistant identity store.

**Assumption-delta note (no-change):** The primary noun is the agent cgroup; its kernel-stamped id is the one identity key. The `SO_PEERCRED` + `/proc/PID/cgroup` fallback is a second WAY to reach that same id, not a second identity key — the equivalence test pins this. No second identity model is introduced.
</objective>
