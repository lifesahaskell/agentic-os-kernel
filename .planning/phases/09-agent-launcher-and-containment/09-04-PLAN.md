**User story (MVP):** **As** the researcher, **I want to** spawn each agent into its own cgroup with a pidfd-resolvable identity, narrowed Landlock and seccomp layers, and subtree freeze and kill, **so that** every later component has an unprivileged principal to key on.

<objective>
Exercise the two degraded paths the launcher must survive — a kernel without `clone3` (spawn falls back to fork+move+exec, 09-01) and a kernel without `PIDFD_GET_INFO` (identity falls back to `SO_PEERCRED` + `/proc`, 09-02) — by forcing each failure with the D-13 shim on a host that actually has both features. Measure what the fallbacks cost (the spawn fork-to-move window; the identity pid-reuse window) and prove the fallback still reaches the correct answer.

Purpose: D-13 says the fallback paths are tested through an external seccomp shim precisely because this host cannot present an old kernel. This plan is where that simulation lives, clearly labelled, so the degraded paths have real evidence without pretending to be a native-old-kernel result.

Output: `tests/fallback.rs` with `spawn_fallback_window` and `identity_fallback_race`, both green in a delegated scope, both labelled simulated.

**Assumption-delta note (no-change):** The fallback is a second ROUTE to the one identity key (the cgroup id), not a second key. `identity_fallback_race` asserts the SO_PEERCRED route resolves the identical `agent_id` as the pidfd route.

**Wave note:** this plan runs in wave 4, after 09-03 and alone. After 09-03 it is written against the real default-deny layer rather than adjusted later. Alone, because every test here does root launches that write the shared registry at /run/user/UID/aok-launch, and register_root prunes dead roots with an unlocked read-modify-write; a sibling plan's suite running in a parallel worktree on the same host could drop a line. 09-05 waits for this plan for the same reason and so that its CPU-pinned reads never overlap a cargo test run.
</objective>
