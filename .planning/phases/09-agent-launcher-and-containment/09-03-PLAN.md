**User story (MVP):** **As** the researcher, **I want to** spawn each agent into its own cgroup with a pidfd-resolvable identity, narrowed Landlock and seccomp layers, and subtree freeze and kill, **so that** every later component has an unprivileged principal to key on.

<objective>
Fill the narrowing layers 09-01 stubbed: `src/landlock.rs` (the D-17 ABI-6 feature set applied from `--grant`, the default grant, the D-12 implicit grants, and the D-14 floor refusal with the floor value read from `tools/aok-launch/aok-launch.conf`) and `src/seccomp.rs` (the D-03 wide allow-list hand-assembled as a `Vec<sock_filter>` and installed with `seccompiler::apply_filter`, with the D-01 ENOSYS-above-table and D-05 arch/x32 errno policy). Prove a sub-agent cannot widen authority, that an `sh -c` grandchild inherits confinement (LNCH-04), that every denial returns the documented errno and the filter reads no pointer (LNCH-06), and that the 16-layer depth cap holds (D-18).

Purpose: this is the protection boundary the whole project is about — authority is exactly the Landlock grant plus the seccomp allow-list, and a sub launch only ever ANDs more restriction. The seccomp library cannot express the needed policy (its `try_from` KILLs on arch mismatch, violating D-05, and it has no number-range compare for D-01), so the filter is hand-assembled in safe Rust; this plan pins exactly why.

Output: complete `landlock.rs` and `seccomp.rs`, a derived syscall (nr,name) table whose derivation, allow ranges and deny set are recorded in the `seccomp.rs` module doc and `09-03-SUMMARY.md` (09-06 writes `09-ALLOWLIST.md` from that record), the `subset`/`registry_confinement`/`errno_contract`/`shellout` integration tests, and the whole crate (09-01 and 09-02 tests included) green under default-deny in one delegated scope.
