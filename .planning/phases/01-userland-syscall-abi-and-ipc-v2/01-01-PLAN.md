<user_decisions_recorded>
- Bootstrap delivery: ring-3 binaries reach the kernel through `include_bytes!` of flat images. No cpio/initramfs in Phase 1.
- Syscall ABI accepted as proposed, no longer [ASSUMED]: `rax` = number; `rdi, rsi, rdx, r10, r8, r9` = arguments; negative errno in `rax`; one `#[repr(C)] IpcArgs` struct for multi-value IPC calls.
- SAFE-01 covers ring-3 code: `libsys` asm blocks get ledger rows in the userland section (the ledger and checker are created by 01-02).
</user_decisions_recorded>

<assumption_delta_decision>
- Signal: `chosen` (the user target changes from a derived stock target to a chosen custom JSON).
- Primary noun: `x86_64-aok-user.json`, the single target for every ring-3 crate (tests now, servers and `libaok` later).
- Decision: promote. The stock `x86_64-unknown-none` target is never used for user code; it stays the kernel's target only. Rationale: the stock target is soft-float with the kernel code model, so user output could not share an ABI with musl-compiled C (STACK.md "What NOT to Use").
