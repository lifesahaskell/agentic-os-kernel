## How the ring-3 store is made without new unsafe

The verification asks for a ring-3 bin that stores to `0xffff_8000_0000_0000`. Making that store through a pointer would need a raw-pointer write in ring 3, and that needs a new ledgered `unsafe` block (a U-07 row). This plan does not add one.

Instead, the ktest starts an ordinary bin with its initial `rsp` pointing into the kernel half. The bin's `_start` (the existing U-02 assembly in `userland/libsys/src/rt.rs`) runs `and rsp, -16` and then `call`. The `call` pushes the return address, which is an 8-byte ring-3 store to `rsp - 8`.

The hardware event is the one CR-01 needs: a #PF (vector 14) taken from ring 3 with `PageFaultErrorCode::WRITE` set and CR2 equal to the store address. OSTD 0.19.0 returns every fault-class exception from user mode as `ReturnReason::UserException` (`arch/x86/cpu/context/mod.rs` lines 386-388). `run_ctx` then passes `pf.addr` to `handle_cow_fault`, which is the path that panics.

The ktest uses two stack values:
- `rsp = 0xffff_8000_0000_0010`. The push lands at `0xffff_8000_0000_0008`, a canonical kernel-half address.
- `rsp = 0`. The push lands at `0xffff_ffff_ffff_fff8`, the top page, where `page + PAGE_SIZE` overflows.

Both targets are canonical, so the CPU raises #PF and not #GP or #SS. The direct ktest in vm.rs covers the exact address `0xffff_8000_0000_0000`. A ring-3 push cannot hit that address, because `rsp = 0xffff_8000_0000_0008` aligns down to `...0000` and the push then lands at a non-canonical address.

## Reachability note: the other vm.rs unwraps

This note covers the `cow_clone` unwraps at vm.rs lines 30, 31, 34, 46 and 48, and the `panic!` and `assert_eq!` next to them at lines 36 and 38. **Finding: ring 3 cannot reach them at HEAD.** Checked from source on 2026-10-26:
- **No syscall clones a space.** The syscall decoder (`kernel/src/syscall.rs` lines 230-273) accepts only exit, sched_yield, futex wait, wake and requeue, call, recv, reply, and reply_recv.
- **Every caller of `cow_clone` is a ktest.** The callers are:
  - ipc.rs lines 874 and 972, both inside the `#[cfg(ktest)]` module that starts at line 678;
  - user.rs lines 376 and 605, inside the test module that starts at line 334;
  - vm.rs's own tests.

  A search for `cow_clone(` in the region of each `kernel/src/*.rs` file before its first `#[cfg(ktest)]` finds only the definition at vm.rs line 27.
- **The callers pass kernel constants as the range:** `IMAGE_BASE..USER_STACK_TOP` and `IMAGE_BASE..DATA + PAGE_SIZE`.

**Residual risk RR-01 (deferred; the orchestrator should report it).** Phase 2 plans 02-06 and 02-07 call `cow_clone` from the procmgr spawn and fork path, and a ring-3 request drives that path. From then on, these sites become ring-3-reachable:
- the parent space's contents (a huge page, or a non-RAM mapping) reach the `panic!` and the `assert_eq!`;
- any range that leaves the user page table reaches the `cursor_mut` unwraps.

*(interpretation)* The `query` and `jump` unwraps hold while the cursor stays inside a range that lies within the user page table. Phase 2 should either establish that or make `cow_clone` fallible when it wires the call. This plan does not change `cow_clone`.

Other ring-3-reachable unwraps outside vm.rs were not audited by this plan.

## WR-03 evidence and residual risk

- **How the branches are closed.** The three allocation-failure branches are closed by inspection plus the source assertions in Task 3, not by a runtime test. The branches: the CoW allocation in `handle_cow_fault`, `LoadError::NoMemory` in `load_image`, and `LoadError::NoMemory` in `map_stack`. OSTD 0.19.0 offers no way to inject a frame-allocation failure:
  - `FrameAllocOptions` has no failpoint.
  - The global frame allocator is one link-time static (`__GLOBAL_FRAME_ALLOCATOR_REF`, `src/mm/frame/allocator.rs` line 181). A failing allocator would apply to every ktest.
  - Exhausting real frames under TCG would risk kernel-heap OOM panics elsewhere.
- **Accepted residual risk RR-02.** No test executes those three branches.
- **Runtime evidence that remains:** the assertion that `Errno::from(AgentError::NoMemory)` equals `Errno::ENOMEM`.
- **The alloc-before-charge order has no cheap runtime test.** The two orders differ observably only when an allocation fails: charge-first would leave a page charged with no frame, and that failure cannot be forced. On a refused charge, both orders leave `mem_used_pages() == 0`. The added quota assertions pin that outcome, not the order. Task 3's source gate pins the order.
- **Deliberately out of scope:** `kernel/src/lib.rs` line 104, `alloc_frame().unwrap()` in the boot-time cpu-budget check setup. Ring 3 cannot reach it.
