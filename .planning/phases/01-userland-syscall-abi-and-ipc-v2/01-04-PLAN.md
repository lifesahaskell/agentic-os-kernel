Purpose: 01-06's 100-capability transfer test, and every Phase 3+ server, need a table that grows. The bound keeps an agent from growing it without limit.

Output: a growable `CSpace` with a free list and `MAX_SLOTS`, plus ktests.
</objective>

  <behavior>
    - Inserting into an empty CSpace returns 0, 1, 2, ... in order
    - After remove(5), the next insert returns 5
    - Inserting MAX_SLOTS capabilities succeeds; the next returns Err(Full)
    - get and remove on an index at or beyond the current length return Err(NoSlot)
  </behavior>
  <action>
    Per KERN-05, change `CSpace` to these fields:
    - `slots: Vec<Option<Cap>>`, starting empty;
    - `free: Vec<usize>`, the indices of `None` slots.

    Replace `pub const SLOTS: usize = 64` with `pub const MAX_SLOTS: usize = 65_536`. That value matches the `syscall::Handle` bound that 01-03 writes in parallel; 01-06 points `Handle` at this constant.

    `insert`:
    1. Pop a free index if there is one.
    2. Otherwise push a new slot while `len < MAX_SLOTS`.
    3. Otherwise return `CapError::Full`.

    `remove` takes the capability and pushes the index onto `free`.

    `get` is unchanged in behaviour. Keep the signatures of `new`, `insert`, `get` and `remove`, so `agent.rs` and `ipc.rs` compile unchanged.

    Add a one-line comment: lowest-free reuse is not guaranteed. POSIX lowest-fd semantics belong to the fd table in the vfs/procmgr phases, not to the CSpace.

    Rewrite `cspace_slots` for the new bound: it fills `MAX_SLOTS` and asserts `Full`. If that is too slow under TCG, it fills a test-only smaller bound instead; do not lower `MAX_SLOTS`. Write it before the implementation and watch it fail against the 64-slot table.
  </action>
