  <action>
    **Committed wait.** In `thread.rs`, split 01-05's `block_until` body into a private core taking an `interruptible: bool`. `block_until` passes true. Add `pub fn block_until_committed<R>(&self, wq, cond) -> R`, which passes false: its cancel closure ignores a pending redirect, takes no deadline, and keeps the fail-points. It is the only uninterruptible wait in the kernel; only `call` uses it, after a Cancel is sent. The redirect stays pending and applies when the thread returns to ring 3, as before.

    **ReplyWait state (IPC-02).** Give `ReplyWait` a state under its own lock:
    - `Queued`: in the endpoint queue;
    - `Received { server: Weak<Thread>, handle }`: in that server thread's reply table;
    - `Replied(words, data, caps)`.

    It also holds `caller: Weak<Thread>` and a `cancel_sent` flag. The endpoint's dequeue moves `Queued` to `Received` while holding the endpoint queue lock, so a cancel and a dequeue cannot both win.

    **Call's wait.** `call` waits with `block_until(..., None)`. On `Interrupted`, under the queue lock:
    - still `Queued`: remove that message from the queue by `Arc::ptr_eq` and return EINTR (not started);
    - already `Replied`: return the reply (a completed reply wins);
    - `Received`: if `cancel_sent` is unset, set it, push the handle onto the server thread's pending-cancel list (`SpinLock<VecDeque<u64>>` on `Thread`), and wake that thread through the waker it published in `state.blocked`. Then wait with `block_until_committed` until `Replied`.

    The pending-cancel list never exceeds `MAX_REPLIES`, because each entry names a live reply-table slot. A Cancel can therefore never be dropped as `Full`.

    **Recv.** The `recv` condition first pops a pending cancel. That is delivered as a message with `label = abi::LABEL_CANCEL`, `reply` = the handle, and no data or caps; it takes no new reply-table slot. Otherwise recv dequeues normally. An interrupt during recv still returns EINTR at once, through `block_until`.

    **Reply.** `reply` to a handle whose `caller` no longer upgrades drops the reply and returns 0, freeing the slot.

    **Decode.** `Call` and `Send` with `label == LABEL_CANCEL` are EINVAL, so ring 3 cannot forge a Cancel. Add `LABEL_CANCEL = u64::MAX` to `abi`.

    **reader bin.** `reader.rs` (`arg` = the SEND slot) keeps its progress in statics: a 64-byte collected buffer, a count, and its `IpcArgs`.
    - `main` loops calling read (label 1, `recv_buf` = the next 8 bytes of the collected buffer), adding the returned length to the count. The server returns length 0 at end of stream.
    - The handler (the redirect target, entered after the interrupted call returns) first adds the reply length the interrupted call wrote into the static `IpcArgs`. It then continues the same loop and exits 0 if the collected bytes equal the stream pattern (byte i = i × 7 mod 251), or 1 otherwise.

    **reply_to_dead_waiter_is_dropped.** This needs a `#[cfg(ktest)]` constructor that builds a `ReplyWait` for a Thread the test then drops. Phase 2's thread teardown is the real trigger.

    - cap_install_is_all_or_none: a receiver CSpace with 2 free slots below MAX_SLOTS gets a 4-cap message: recv returns EMFILE, no slot changes, the message is still queued; after removing 2 more slots recv installs all 4

  <action>
    **Sending (IPC-05).** Remove the remaining nonzero-`ncaps` guard. Add `abi::MAX_IPC_CAPS = 4` and `errno::EMFILE = 24`; `ncaps > MAX_IPC_CAPS` is EINVAL. At send, call and reply time, in the sender's context, for each `i < ncaps`:
    1. Look up `caps[i]` in the sender's CSpace; a missing slot is EBADF.
    2. Take `Cap::derive(Rights(cap_rights[i]))`. That requires GRANT and masks the rights; `CapError::Rights` maps to EPERM.

    The derived copies travel in `Message.caps` (or the `Replied` state). The sender keeps its own copy, and revocation reaches the derived copies through the shared target.

    **Receiving.** In the receiver's context, at `recv`, install every carried cap into its agent's CSpace, or none:
    - Check free capacity first: free-list length plus `MAX_SLOTS - len`.
    - Without room, return EMFILE and leave the message at the queue front, still `Queued`.
    - Write the new slots into `IpcArgs.caps`, their rights into `cap_rights`, and the count into `ncaps`.

    **Replies.** For a reply, the server's `reply` installs into the caller agent's CSpace under the same rule. Without room it returns EMFILE to the server and leaves the reply-table entry in place. Installing a CSpace entry touches no user memory, so doing it from the server's context is sound.

    **Handle bound.** Point `syscall::Handle`'s bound at `crate::cap::CSpace::MAX_SLOTS`, replacing 01-03's literal.

    **cap_recv bin.** `cap_recv.rs` (`arg` = its RECV slot; the forward target's SEND slot is `arg + 1`):
    1. receive the SEND|GRANT copy;
    2. forward it with mask ALL;
    3. try recv on it, expecting EPERM;
    4. receive the SEND-only copy;
    5. try to forward it, expecting EPERM;
    6. exit 0, or the failing step.

    **Tests.** Write the three ktests in `ipc.rs`'s ktest module. These stand in for the REQUIREMENTS test (a file capability passing from vfs through exec): those servers arrive in Phases 3 and 4, and the transfer path they use is this one.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → server | A caller can interrupt itself at any point of a call |
| sender → receiver | Capabilities cross agents; rights must never grow |
| server → caller | A server can stall a cancelled caller |
