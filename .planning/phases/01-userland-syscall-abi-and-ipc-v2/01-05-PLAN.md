**As a** server author, **I want to** have a Rust ring-3 toolchain, a fuzz-safe syscall ABI and call/reply IPC, **so that** servers can run and the IPC cost is known.

<objective>
Build IPC v2's core on one blocking primitive:
- `block_until` with deadlines (KERN-12);
- kernel-held reply handles with deferred reply and `reply_recv` (IPC-01);
- tid/tag stamping (IPC-03);
- bulk data by kernel copy with a CoW break (IPC-04).

Purpose: Phase 3 servers (vfs, procmgr) park requests and move file data. 01-06's Cancel-then-wait builds on the reply table and on `block_until`.

Output: `block_until` and its fail-point ktests, the reply table and three new syscalls, the tid/tag fields, the bulk path, and four ring-3 test programs.
</objective>

<user_decisions_recorded>
- The syscall ABI is accepted as proposed. New calls continue from `0x100`: `SYS_RECV = 0x101`, `SYS_REPLY = 0x102`, `SYS_REPLY_RECV = 0x103`. All carry an `IpcArgs` pointer; numbers are never reused.
- The IPC copy path is the SKELETON decision. The kernel stages bytes, then copies them in each side's own syscall context through `copy_from_user`/`copy_to_user`. This deliberately departs from RESEARCH's frame-level cross-space copy, because the OSTD `VmSpace` reader and writer work only on the active space. One CoW-breaking write path (KERN-06) is kept.
</user_decisions_recorded>

| Boundary | Description |

| caller → server | Request bytes, label and buffers are untrusted; identity is kernel-stamped |
| server → caller | Reply handles must only answer the call they were issued for |
