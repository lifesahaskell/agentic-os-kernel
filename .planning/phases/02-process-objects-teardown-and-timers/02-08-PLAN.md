**As a** procmgr author, **I want to** have Space and Thread capabilities, full process teardown and timers, **so that** processes can be created, signalled and destroyed without leaks.

<objective>
The kernel-held signal-frame stack and `SYS_SIGRETURN` (KERN-11; OD-01, OD-16). A redirect pushes `{UserContext, FpuContext, FS base}` onto a per-thread stack inside the kernel and moves the handler's `rsp` below the red zone. `SYS_SIGRETURN` pops the frame and restores everything. Nothing is written to user memory.

This plan is a DRAFT written against the post-01-07 tree (OD-10), on top of 02-04 to 02-07. Re-check after 01-07 lands:
- Task 2: the ledger id is U-07 (01-07 took U-04 `testpage::test_page`, U-05 `clock::tsc` and U-06 `trap::ud2`), and the `userland/libsys/src/lib.rs` doc line (lines 1-3, now "the three small modules below (ledger rows U-01 to U-06)") becomes four modules and U-01 to U-07.
- Task 3: whether 01-07 added a libsys futex wrapper that the `sigreturn` bin's mode 2 can use in place of the raw call.

Purpose: success criterion 2, second half. procmgr's signal delivery (SIG-01/02, Phases 4-5) needs a return path that survives any handler, and the Phase 6 musl signal tests need registers and FPU state to survive. A frame on the user stack would be the classic design, and it is the one OD-01 rejects: the kernel would write user memory, and user code could forge the frame.

    **thread.rs: the frame stack.**
    - `pub struct RedirectFrame { ctx: UserContext, fpu: FpuContext, fs_base: usize }`.
    - `pub const MAX_FRAMES: usize = 8`, `pub const RED_ZONE: usize = 128`, `pub struct FramesFull`.

    **thread.rs: `try_interrupt` and `interrupt`.**
    - `try_interrupt(&self, entry) -> Result<(), FramesFull>` takes the frames lock, refuses when the stack holds `MAX_FRAMES`, and otherwise does what `interrupt` does today while still holding it.
    - A second interrupt before the first is applied replaces the pending entry, as today. So the frame count plus the pending redirect never exceeds 8.
    - `interrupt` keeps its signature for the existing kernel-side callers (ktests and the boot checks in `lib.rs`). It calls `try_interrupt` and ignores `FramesFull`; its doc comment states that a full stack drops the redirect, and that ring-3 paths use `try_interrupt`.

    **thread.rs: `apply_redirect(&self, ctx: &mut UserContext) -> bool`.**
    1. When no redirect is pending, return false. Only this thread takes its own redirect, so a pending one cannot vanish between steps.
    2. Snapshot the FPU before taking the IRQ-safe frames lock, because the clone allocates. Under `FPU_OWNER`:
       - when the owner is this thread's `fpu`, call `save()` on it first: the kernel is soft-float, so the CPU still holds the user's registers;
       - then clone it.
    3. Take the frames lock, then take the redirect.
    4. Push `RedirectFrame { ctx: ctx.clone(), fpu, fs_base: self.fs_base() }`.
    5. Set `rdi` to the old `rip` and `rip` to the handler.
    6. Set `rsp` to `((rsp - RED_ZONE) & !15) - 8`, with wrapping arithmetic. A non-canonical result faults in the handler, which is the handler's problem.
    7. Return true.

    The handler starts with the interrupted FPU state, unchanged, which keeps the existing `fpu` handler tests valid. This step writes no user memory.

    **thread.rs: `pop_frame`, `restore_frame`, `frame_depth`.**

      - calls `set_fs_base(f.fs_base)`;
      - under `FPU_OWNER`, writes `f.fpu` into this thread's `fpu`, and clears `FPU_OWNER` when it points here, so `pre_user_run` loads the restored state.
    - `frame_depth()` returns the stack length.

    Per OD-01 and OD-16. The probe needs every register under its control with no compiler code in between, which only asm can promise. That is why it is a ledgered libsys module, not code in the bin.

    **regs.rs** is a new libsys module, with `pub mod regs;` in lib.rs. Update lib.rs's doc line that lists the asm modules.

    It holds these statics, all addressed RIP-relative from the asm, so no register is needed to reach them:
    - `GPR_WANT: [u64; 15]`: distinct non-zero patterns for rax, rbx, rcx, rdx, rsi, rdi, rbp, r8-r15, in that order;
    - `XMM_WANT: [u64; 32]`: distinct non-zero quads built by a `const fn`;
    - `DONE`, `RSP0`, `HANDLER_RSP`, `HANDLER_PC`;
    - `GPR_GOT: [u64; 15]` and `XMM_GOT: [u64; 32]`.

    It also holds `regs_probe!()`, a macro in the style of `entry!`, which defines `_start` and `_aok_handler` with `global_asm!` under `#[allow(unsafe_code)]` and a `// SAFETY: U-07` comment. U-07 is the next free Userland id; 01-07 took U-04, U-05 and U-06.

    `_start`:
    1. Store rsp into `RSP0`.
    2. Fill `[rsp - 4096, rsp)` with a canary quad using `rep stosq`, which leaves rsp unchanged.
    3. Load xmm0-xmm15 from `XMM_WANT`.
    4. Load each of the 15 general registers from `GPR_WANT`, rsp excluded.
    5. Spin on a compare of `DONE` with zero. The spin uses no register.
    6. Once `DONE` is set, store all 15 registers into `GPR_GOT` and xmm0-xmm15 into `XMM_GOT`.
    7. Move rsp 16 KiB below `RSP0`, so the Rust check's frames stay out of the canary range, and align it.
    8. Call `regs::check`, then exit with its result.

    `_aok_handler` uses no stack:
    1. Store rsp into `HANDLER_RSP` and rdi into `HANDLER_PC`.
    2. Zero every general register except rsp, and every xmm register.
    3. Set `DONE`.
    4. Issue `SYS_SIGRETURN` with `mov eax, 0x108` and `syscall`.
    5. If that returns, exit 41.

    `regs::check() -> u64` returns:
    - 0 when everything matches;
    - 1 + i for the first general register i that differs from `GPR_WANT` (so rbx is 2);
    - 20 + i for the first xmm register that differs;
    - 40 when a canary quad changed;
    - 45 when `HANDLER_RSP` is not `((RSP0 - 128) & !15) - 8`;
    - 46 when `HANDLER_PC` is zero.
