<objective>

- Task 2: the `task()` / `is()` helpers in the `sched.rs` test module, and its imports (`prog` is gone after 01-07).

Purpose: OSTD has no idle task. `ReschedAction::Retry` busy-spins the vCPU at 100% whenever every agent is blocked (02-RESEARCH Pattern 3, Pitfall 1). Every later timer and teardown test assumes a quiet CPU.

Output: an idle task in `BudgetScheduler`, a boot-time halt check, four `sched_*` ktests, an exact OSTD pin and `tools/pin_check.sh`.
</objective>

    Per 02-RESEARCH Pattern 3 and OD-10.

    **Idle marker and counter (sched.rs).** Add a zero-sized `pub struct Idle;` used as the idle task's `Task::data()`, and `fn is_idle(task)` that downcasts to it. Add `pub static IDLE_HALTS: AtomicU64`. The idle body is a loop of `ostd::task::halt_cpu()` followed by one `IDLE_HALTS` increment. `halt_cpu` already calls `might_preempt` after waking, so the body needs no yield. Do not hand-write `hlt`: `halt_cpu` handles the IRQ-enable and need-preempt race and needs no `unsafe`.

    **Spawn.** `install()` spawns the idle task last, after `inject_scheduler`, with `TaskOptions::new(..).data(Idle).spawn()`.

    **Run queue.** `RunQueue` gains `idle: Option<Arc<Task>>`. The idle task lives in this slot or in `current`, never in `queue`. That placement is what keeps it out of the "others" count; do not filter it out of `queue` instead.
    - `enqueue`: an idle task goes into the slot after the same `schedule_info().cpu` handshake other tasks get, and returns `None`. Any other task is pushed to `queue` and returns `Some(CpuId::bsp())` when `current` is idle or `None`, else `None`.
    - `pick`: first take the first eligible task in `queue`. If there is none, take the idle task from the slot. If both are absent, return `None` (pre-install behaviour). A previous current that was idle goes back to the slot; any other previous current goes to the back of `queue`.
    - `update`: `others` stays `queue.iter().any(eligible)`.
      - Tick with idle current returns `others` and charges nothing.
      - Tick with a non-idle current charges it as today and returns `others || !eligible(cur)`. An out-of-budget current with nothing else eligible therefore switches to idle.
      - Yield returns `others`.
      - The blocking and exit flags (OSTD's non-Tick, non-Yield `UpdateFlags`; read the 0.19 enum for the variant names) return `others || self.idle.is_some()`. The protocol requires true whenever `pick_next` can return a task.
    - Update the `BudgetScheduler` doc comment: the boot task is no longer the idle fallback.

    **Boot check (lib.rs).** Add `fn idle_halt_check() -> bool`, run first inside the boot check task before any user image starts, so only the boot task and idle exist.
    - Record `IDLE_HALTS` and `Jiffies`, then block for N = 50 ticks with `Thread::block_until` on a fresh `WaitQueue`, a never-true condition and a deadline. Use a throwaway root-agent `Thread`, exactly as `block_until_times_out` does.
    - Pass when at least N ticks elapsed and the halt delta is in [N/2, 4N].
    - A spinning idle gives millions; an idle that never runs gives 0.
    - Print `aok: idle halts H over E ticks`, then `aok: idle halt check passed` or `FAILED`, and fold the result into the poweroff exit code with the existing checks.
    - Replace the `cpu_budget_check` yield loop that waits `RUN_TICKS` with the same timed block, so idle (not the boot task) is the fallback when both agents are out of budget.
    - The budget assertions are upper bounds, so they must still hold. Record the before and after `aok: N periods:` line in the SUMMARY.

    **check.sh.** Add `"aok: idle halt check passed"` to the `for want in ...` list.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ring 3 → scheduler | Untrusted threads' budget state decides what runs; idle must not let one starve the others or run past budget |
| toolchain → kernel binary | The OSTD and nightly versions decide the unsafe code the kernel relies on |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-03 | Denial of service | idle busy-spins (vCPU at 100%) | low | mitigate | Boot check upper bound of 4N halts over N ticks |
| T-02-04 | Tampering | silent OSTD or nightly drift changes kernel behaviour | low | mitigate | Exact `=0.19.0` requirement and `tools/pin_check.sh` in `check.sh`, self-tested |
</threat_model>
