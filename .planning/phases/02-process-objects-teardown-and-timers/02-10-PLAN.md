**As a** procmgr author, **I want to** have Space and Thread capabilities, full process teardown and timers, **so that** processes can be created, signalled and destroyed without leaks.

<objective>
The thread-lifecycle calls musl start-up needs (OD-03):
- `arch_prctl` `ARCH_SET_FS` / `ARCH_GET_FS` at Linux number 158;
- `SYS_EXIT_UNMAP` (0x109), which unmaps a range and exits the thread in one call so a detached thread can free its own stack;
- the exit-time clear-and-wake of the `clear_tid` word that 02-04's `ThreadCtx` carries but refused.

It sits under KERN-04 because it completes the `thread_create(space, ctx, tag)` contract: 02-04 shipped the `clear_tid` field and rejected any non-zero value until this plan. The calls are also LIBC-04's kernel side. LIBC-04 is Phase 6's requirement and is verified there with musl, so this plan does not list it.

    **thread.rs.** `Thread` gains `clear_tid: AtomicUsize`, 0 by default, with `set_clear_tid(va)` and `clear_tid() -> usize`.

    **space.rs: `thread_create`.**
    - Step 1 no longer rejects every non-zero `clear_tid`. 0 means none. Any other value must be 4-aligned and lie in `[PAGE_SIZE, USER_TOP - 4]`, else `Invalid`.
    - Step 7 calls `th.set_clear_tid(start.clear_tid)` before `user::spawn_thread`.
    - Update `thread_create_refuses_bad_ctx` as `<behavior>` says.

    **space.rs: `pub fn clear_child_tid(&self, th: &Thread)`.**
    1. `va = th.clear_tid` swapped to 0. Return when it was 0, so the step runs at most once per thread.
    2. Take the `mm` lock (02-09). Return when `is_dying()`: a killed space has no surviving thread to observe the word. Taking the lock also keeps the write from being charged after teardown's uncharge.

    4. Ignore EFAULT, ENOMEM and any futex error. The thread has already exited, and Linux ignores the same faults.

    This lock order, `mm` then the copy's charge, then the futex table spinlock, matches 02-09's: no mm path takes the futex lock.

    **user.rs.** At every thread exit point (the `spawn_thread` task, `start` and `run`), call `space.clear_child_tid(&thread)` first, before `set_exit`, `note_exit` and `reap`. Linux clears the word in `mm_release`, before the parent is notified. The thread's vm is still the active one there, because `activate_current_space` reloads it for the current thread. `start` and `run` threads have no `clear_tid`, so the call returns at step 1.

    **syscall.rs: ExitUnmap dispatch.** Before the munmap, when `t.clear_tid()` lies inside `[addr, addr + page_up(len))`, call `t.set_clear_tid(0)`. Linux would write into that range after the unmap, possibly into a mapping a sibling has since placed there. Skipping it is a choice only this new call makes, and no POSIX interface changes.

    3. Run the timed wait and the checks from `<behavior>`, exiting 0 on success.

    The child gets its own stack, so main's stack is never shared.

    **Ktests.** The tests in `<behavior>`. Then run the full suite.
