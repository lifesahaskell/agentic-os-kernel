**As a** procmgr author, **I want to** have Space and Thread capabilities, full process teardown and timers, **so that** processes can be created, signalled and destroyed without leaks.

<objective>
The self-memory calls: `mmap`, `munmap`, `mprotect` and `brk` on the caller's own space, charged through the space's ledger (AGNT-02; OD-02, OD-12). Anonymous private mappings are populated eagerly, so a mapping past the budget fails at the call with `ENOMEM` instead of at a later fault. `brk` and the `PROT_NONE` reservation follow Linux, because musl's allocator and thread stacks use them unchanged in Phase 6.

AGNT-02 names three legs. This plan delivers the memory leg: `ENOMEM` from a ring-3 `mmap`. The `EAGAIN` legs (thread and timer limits) landed in 02-02 and 02-04. The `SIGXCPU` leg is SIG-03's, per OD-12; this plan sends no CPU-budget signal.

    **syscall.rs: decode.** `Syscall::Mmap { addr, len, prot, flags, off }` decodes from `SYS_MMAP`, with the fd in `a[4]` ignored (it is ignored for anonymous mappings on Linux). Checks run in this order, so a call with several faults gets one fixed errno:
    1. `len` 0 is EINVAL.
    2. `prot` bits outside READ, WRITE and EXEC are EINVAL.
    3. `flags & 3`:
       - 0 is EINVAL;
       - `MAP_SHARED`, or the value 3, is ENOTSUP.
    4. A missing `MAP_ANONYMOUS` is ENODEV. File mappings belong to libaok through vfs.
    5. An offset that is not page-aligned is EINVAL.
    6. `MAP_FIXED` with an unaligned `addr` is EINVAL.
    7. A `len` whose page round-up overflows is ENOMEM.

    Other flag bits are ignored, as Linux ignores unknown mmap flags.

  <action>
    Per OD-02 and the "Self-memory calls" bullets in 02-OPEN-DECISIONS.md.

    **The COW rule.** A page carries `COW` if and only if it is logically writable and its frame may be shared. `vm::cow_clone` and `handle_cow_fault` already keep that invariant. Every mprotect path below keeps it too, so no other code needs to change.

    **space/mmap.rs: munmap.** `pub fn munmap(&self, addr, len) -> Result<usize, Errno>`:
    1. EINVAL for an unaligned address, `len` 0, or a range that leaves `[0, USER_TOP)`.
    2. Under `mm`, trim or split every overlapping record. A split that would pass `MAX_MAPS_PER_SPACE` is ENOMEM, checked before anything changes, as on Linux.
    3. Unmap the range in one `cursor_mut` `unmap(len)` call and keep the page count it returns.
    4. Flush the range through `flusher()`.
    5. Uncharge that count through `self` as `Payer`, and return it.

    It covers anything mapped, image and stack pages included, as Linux does. Frames that a cow-cloned child still shares follow the 02-06 under-charge rule, which is recorded there.

    **space/mmap.rs: PROT_NONE.** `mmap` with `PROT_NONE` inserts its record without populating it.

    **space/mmap.rs: `MAP_FIXED`.** It replaces the Task 1 ENOTSUP:
    1. ENOMEM for a range outside `[PAGE_SIZE, USER_TOP)`.
    2. Run munmap's steps over the range.
    3. Map it as usual.

    When the populate fails, the old pages stay gone and the call is ENOMEM, as Linux leaves them.

    **space/mmap.rs: mprotect.** `pub fn mprotect(&self, addr, len, prot) -> Result<(), Errno>`:
    1. EINVAL for an unaligned address, unknown `prot` bits, or a range that leaves user space.
    2. First pass, under `mm`, changing nothing: every page must be mapped in the page table or inside a record, else ENOMEM. Count the unmapped pages that lie inside records.
    3. When `prot` is not `PROT_NONE`, charge that count in one call.
    4. Second pass, over each page:
       - an unmapped page inside a record is populated with the new flags;
       - a mapped page is changed with `protect_next`:
         - write granted and `frame.reference_count() > 1`: set `COW` and leave `W` clear;
         - write granted otherwise: set `W` and clear `COW`;
         - write not granted: clear both;
         - R and X follow `prop_flags(prot)`.
    5. Update the `prot` of every record the range touches, splitting where needed and counted against the limit.
    6. Flush the range.

    **futex.rs.** In `lookup`, the `MappedRam` arm takes `prop` as well as `frame` and returns `FutexError::Fault` when `prop.flags` lacks `PageFlags::R`. The copy-on-write break before it needs no change: mprotect to `PROT_NONE` clears `COW`, so it does nothing on such a page. Without the check, a futex on a `PROT_NONE` page reads through the frame, where Linux gives EFAULT.

    **syscall.rs.**
    - `Syscall::Munmap { addr, len }` and `Syscall::Mprotect { addr, len, prot }` decode from `SYS_MUNMAP` and `SYS_MPROTECT`.
    - Dispatch runs both on `t.process()`; no process is ENOMEM.
    - munmap returns 0 on success, not the page count.
    - Add decode-test lines for 9, 10 and 11.

    **mmap.rs.** Mode 2 runs these steps in order and exits the first failing case number, or 0:
    1. mmap 2 pages READ|WRITE.
    2. mprotect page 0 to NONE; the futex probe on it is `-EFAULT`.
    3. mprotect it back to READ|WRITE; the probe is `-EAGAIN`.
    4. munmap page 1; the probe on it is `-EFAULT`.
    5. munmap page 1 again, over a hole: 0.
    6. mmap `PROT_NONE` 1 page; the probe is `-EFAULT`.
    7. mprotect that page to READ; the probe is `-EAGAIN`.
    8. mmap `MAP_FIXED` at the page 1 address; it returns that address.
    9. mprotect a never-mapped range at `MMAP_TOP - 2 * PAGE_SIZE`: `-ENOMEM`.
