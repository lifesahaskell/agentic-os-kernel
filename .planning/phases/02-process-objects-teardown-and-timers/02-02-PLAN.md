**As a** procmgr author, **I want to** have Space and Thread capabilities, full process teardown and timers, **so that** processes can be created, signalled and destroyed without leaks.

<objective>
Add timeouts to futex wait and IPC `recv` / `reply_recv`, and a timer that delivers a message to an endpoint (KERN-09).

This plan is a DRAFT written against the post-01-07 tree (OD-10). 01-07 is an external prerequisite. Re-check after 01-07 lands:
- Task 1: the decode test assertion `err(SYS_FUTEX, [0x1000, 0, 0, 1, 0, 0])` and the fuzz targeted case `(SYS_FUTEX, [mapped, 0, 0, 1, 0, 0], ENOSYS)`. 01-07 may move or rename them, and the fuzz setup's `user_image!("tracer")` may change.
- Task 3: testkit's `spawn_image` and `join` signatures in `user.rs`.

Purpose: `pthread_cond_timedwait`, `nanosleep` and procmgr's `alarm` all need a timed wait or a timer message. The futex decode still answers ENOSYS for any timeout (`syscall.rs:237` shortcut).

Output: `futex::wait_until`, `Endpoint::recv_until` / `recv_parked_until`, `Endpoint::push_kernel`, `kernel/src/ipc/timer.rs`, `SYS_TIMER_ARM`, `abi::Timespec`, the kernel label range, and ring-3 bin `timeout`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ring 3 → futex / recv decode | Untrusted timespec pointers and timeout values |
| ring 3 → timer table | Untrusted arm requests consume kernel memory and timer-task time |
| kernel → endpoint | Kernel-made messages must not be forgeable from ring 3 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Spoofing | ring 3 sending `LABEL_TIMER` (forged timer message) | high | mitigate | `push` refuses every label at or above `LABEL_KERNEL_BASE`; `timer_msg_label_is_reserved` asserts it |
| T-02-06 | Denial of service | unbounded `ARMED` growth | medium | mitigate | 16 per agent (EAGAIN), delay capped at 600,000 ms (EINVAL); `timer_msg_limits` |
| T-02-07 | Denial of service | endpoint lock or allocation in IRQ context | high | mitigate | IRQ path only wakes; the push is in the timer task; acceptance gate forbids a second `register_callback` |
| T-02-08 | Tampering | arithmetic overflow in timespec to ticks | medium | mitigate | Saturating arithmetic, EINVAL for negative or out-of-range nsec; fuzz targeted cases |
| T-02-09 | Denial of service | full endpoint loses a timer | low | mitigate | Re-armed at now + 1 until it fits; `timer_msg_full_queue_retries` |
</threat_model>
